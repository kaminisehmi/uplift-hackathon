What earns the score

  • End-to-end pipeline is fully implemented — src/uplift/ contains analyst, scanner, migrator, verifier, orchestrator (5 real modules, not stubs).
  • Runs with a single command — python -m uplift upgrade pydantic goes from broken repo to green in one shot, reproducible via git checkout demo-v1-state.
  • Proof-of-concept is real, not slides — 77/77 tests green, reports/upgrade-report.json is machine-generated, UPGRADE_REPORT.md is human-readable output.
  • Four Bob custom modes with file-regex permissions — architecture enforces separation of concerns; .bob/custom_modes.yaml is in the repo.
  • Parallel execution — migrator A and B run via concurrent.futures.ThreadPoolExecutor; verifier retries up to 2× automatically.
  • watsonx Orchestrate integration — ADK agent YAML + upgrade_status_tool.py + Granite summarizer; orchestrate/README.md has import steps.
  • 10 bob_sessions JSON files — full task trail from task00_init through task06_final_readme.
  • IBM technology is explicit — Bob IDE (6 features named), watsonx.ai Granite 3.3 8B, watsonx Orchestrate approval gate.
Half-point deduction: Usage scanner and analyst fall back to pre-populated reports/ JSON if files already exist — live Granite inference during the demo requires those files to be deleted first. A judge watching without that knowledge may not see the LLM call in action.
Easy fix: Add a --force flag to python -m uplift upgrade pydantic that deletes the reports and runs the full AI-inference path end to end.

Novel design choices

  • Document-to-code pipeline — treating a human-written migration guide as the source of truth is a genuinely new approach to migration tooling.
  • Breaking-change IDs as a contract — every patch is traceable to a BC-xxx ID; a confidence threshold gates what gets auto-applied vs. flagged.
  • Parallel migrators with file-regime separation — migrator A owns models.py; migrator B owns everything else; no merge conflicts by design.
  • Human-in-the-loop gate via watsonx Orchestrate — the Granite summarizer + approval agent adds an enterprise-grade approval workflow on top of the automated migration.
  • Bob as the agentic runtime — four custom modes are Bob subagents, not just scripts; this is a showcase of Bob's multi-agent capability, not just its code editor.
Half-point deduction: The "read any migration guide" generality is claimed but only pydantic is demoed. Judges may dock points for a single-library proof of concept.
3 · Design & Usability
4 / 5
Good (improved by dashboard)

What works well

  • One-command UX — python -m uplift upgrade pydantic is the entire interaction for a developer; no config files, no recipe authoring.
  • Human-readable output — UPGRADE_REPORT.md is formatted for an engineering manager, not just a machine.
  • Needs-human-review discipline — the system explicitly surfaces what it is not confident about rather than silently guessing.
  • Dashboard added — 5-tab live web UI (./dashboard/start.sh) with Overview, Breaking Changes, Usage Map, live Test Runner, and Full Report — zero new dependencies (stdlib http.server).
  • watsonx Orchestrate approval gate — the engineering-manager UX is a conversational chat: "do you approve or reject merging this branch?" — production-realistic.
One-point gap: Before the dashboard, the only output was a terminal log and a markdown file. Judges scoring "design and usability" expect something a non-developer could interact with. The dashboard closes most of this gap but was added after initial submission.
To push to 5/5: Add a one-click "Run Migration" button in the dashboard that streams the python -m uplift upgrade pydantic live log into the browser.

Scalability argument

  • Any library with a migration guide — SQLAlchemy 1→2, Django 3→4, NumPy 1→2 all have migration guides; UpLift's pipeline is library-agnostic by design.
  • Any repo size — the scanner and migrators operate on file lists from usage-map.json; adding more files only adds more migrator tasks, not more complexity.
  • Enterprise-scale with Orchestrate — the watsonx Orchestrate approval gate means the same agent can serve thousands of microservices across an org, each requiring an explicit manager sign-off.
  • Security angle — dependency upgrades are the fastest path to patching known CVEs; UpLift removes the 30–90 day manual-work lag that keeps vulnerable versions in production.
  • Cost efficiency — < 7 Bobcoins (≈ IBM Granite inference tokens) for a complete migration that would cost a senior engineer 1–2 days; ROI is orders of magnitude.
