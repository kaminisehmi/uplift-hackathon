The problem

Upgrades get deferred for months

  • Dependabot bumps the version. The build explodes. The PR rots.
  • Days of manual work per service to fix the breaking changes.
  • So known-vulnerable versions stay in production.
  • pydantic v1→v2 changes six API surfaces at once.
Built by an agent crew in IBM Bob

Four custom modes,
locked to their own files

  • changelog-analyst — reads the migration guide, docs only
  • usage-scanner — read-only, maps every affected line
  • code-migrator ×2 — run in parallel, cannot touch tests/
  • verifier — runs pytest, fixes, retries until green

11 Bob tasks · 40 Bobcoins · every receipt committed in bob_sessions/

IBM watsonx

The agent recommends.
A human releases.

  • watsonx Orchestrate — Upgrade Approval Agent demands an explicit approve / reject before merge
  • watsonx.ai Granite — reads the migration guide for a library UpLift has never seen
  • The model reads prose. Every stage that touches code stays deterministic.
Why it's different
  • Dependabot / Renovate — bump the version, never fix the code
  • OpenRewrite — fixes code, but needs a hand-written recipe per library
  • AWS DevOps Agent — ops-side, after deployment
  • UpLift — reads the guide the library already published. Pre-merge, in the IDE. No recipe.

SQLAlchemy 1→2 · NumPy 1→2 · Django — same crew, different guide.
